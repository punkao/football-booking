# FIX-PROMPT — แก้เว็บ "ลูกหนัง อารีน่า" หลังผลทดสอบ (เฟส 7.5)

คุณคือนักพัฒนาที่ดูแลเว็บใน `football-booking/web/` (เว็บสร้างตาม `docs/08-BUILD-PROMPT.md`)
ทีมทดสอบอิสระรัน e2e แล้วไม่ผ่านเกณฑ์ และร้านตอบคำถามเพิ่ม (`01-INTERVIEW.md` A-18–A-26) งานนี้คือ**แก้เว็บให้ตรง requirement** ไม่ใช่แก้ให้ test ผ่าน

## อ่านได้
- `docs/04-REQUIREMENTS.md` — **แหล่งความจริงเดียว** (อ่าน BR-13, BR-15, BR-19, BR-24, BR-25, BR-26, BR-27, BR-28, NFR-03, NFR-08, NFR-09, NFR-13 และส่วนที่ 6 ท้ายไฟล์ให้ละเอียด)
- `docs/01-INTERVIEW.md` (ตาราง A-17–A-26) · `docs/08-BUILD-PROMPT.md` (กติกาเดิมทั้งหมดยังใช้)
- `docs/trace/phase6-7-tests.md` (รายงานข้อบกพร่อง) · `docs/05b-EXPLORATION.md` ส่วน "ข้อสังเกต" (F-01–F-07)
- ทุกอย่างใน `web/`

**ห้ามเปิดหรือแก้** `e2e/` ทั้งโฟลเดอร์ (แก้ให้ตรง requirement ไม่ใช่ตรง test) · **ห้ามแก้** `docs/` · ห้ามเปลี่ยน seed เดิม รหัส error เดิม ข้อความเดิม และ `data-testid` เดิม (ยกเว้นที่สั่งในไฟล์นี้)

## กติกา UI ที่ใช้ทุกข้อด้านล่าง
ปุ่มที่ทำไม่ได้ในตอนนั้น: **ยังอยู่และกดได้** แต่แสดงเหตุผลไว้ใต้ปุ่มก่อนกด (`data-testid="<testid ของปุ่ม>-hint"`, ผูก `aria-describedby`) · กดแล้วได้ error เดียวกับ API ใน `error-message` · ยกเว้นช่องติ๊กชั่วโมงฟรี (ข้อ 9) ที่ต้อง disabled

## BUG_MODE
บั๊ก 3 ตัวใน `BUG_MODE=1` ต้องยังเหมือนเดิมทุกอย่าง (`web/BUGS.md`) · ข้อแก้ทั้งหมดข้างบนต้องทำงานทั้งในโหมด 0 และ 1

## ตรวจเองก่อนส่ง
1. `cd web && docker compose up -d --build` → 2 container healthy · `/api/health` = `{ok:true, db:true}`
2. เพิ่มข้อตรวจใน `web/selfcheck/rules-check.mjs` สำหรับข้อ 1–10 (ค่าขอบทุกข้อ) · `BUG_MODE=0` ผ่านทั้งหมด · `BUG_MODE=1` ล้มเฉพาะ 3 ข้อของบั๊กที่ฝัง · **กลับเป็น `BUG_MODE=0` ก่อนส่ง** และ `POST /api/test/reset` ด้วย `{}` (ไม่ล็อกเวลา)
3. unit test และ lint ผ่าน
4. จับภาพใหม่เฉพาะหน้าที่เปลี่ยน ไว้ที่ `web/selfcheck/screens/` (ชื่อขึ้นต้น `p75-`) ทั้ง 1280 และ 375 px · ไม่มี console error ที่ไม่ได้ตั้งใจ · ไม่มีเลื่อนแนวนอนที่ 375 px
