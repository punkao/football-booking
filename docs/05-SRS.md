## 1. บทนำ

### 1.1 วัตถุประสงค์
กำหนดความต้องการของเว็บจองสนามฟุตบอลหญ้าเทียม "ลูกหนัง อารีน่า" ให้ทีมสร้างเว็บ (เฟส 4) และทีมทดสอบ (เฟส 6–7) ใช้เป็นข้อตกลงเดียวกัน

### 1.2 ขอบเขต
ระบบให้ลูกค้าจองและจ่าย (จำลอง) เอง จัดการยกเลิก เลื่อน เครดิต จองประจำ ของเช่า สมาชิก หารค่าสนาม และหาทีมคู่แข่ง พร้อมหน้าร้านสำหรับพนักงาน ผู้จัดการ และเจ้าของ ขอบเขตที่ไม่รวมอยู่ใน `02-BA.md` ส่วนที่ 1

### 1.3 คำศัพท์

| คำ | ความหมาย |
|---|---|
| รอบ | ช่วง 1 ชั่วโมงที่เริ่มตรงชั่วโมง (BR-02) |
| ราคากลางวัน / ราคาเย็น | `Field.dayRate` / `Field.eveningRate` (BR-07, BR-08) |
| มัดจำ / จ่ายเต็ม | `paymentPlan` = `DEPOSIT_50` / `FULL_100` (BR-11) |
| เครดิต | ยอดที่ร้านคืนให้ใช้ครั้งหน้า ไม่คืนเงินสด (BR-15) |
| จองประจำ | `RecurringSeries` (BR-18 – BR-21) |
| คำท้า | `Challenge` (BR-28) |
| สถานะกันสนาม | สถานะ `Booking` ที่ห้ามคนอื่นจองทับ (`04` ส่วน 1.2) |

### 2.4 สภาพแวดล้อม
เว็บเบราว์เซอร์ Chromium / Firefox / WebKit (Safari) บนคอมพิวเตอร์และมือถือ · server รันด้วย docker compose บน Windows (NFR-14)

### 2.5 ข้อจำกัดในการออกแบบ
Next.js + PostgreSQL 16 ใน 2 container · ไม่ใช้บริการภายนอก (การจ่ายเงินจำลอง, ไม่มี API key) · ข้อกำหนดการทดสอบ NFR-09 – NFR-12

### 2.6 สมมติฐานและสิ่งที่พึ่งพา
- คำตอบร้าน A-01 – A-14 (`01-INTERVIEW.md` v3)
- เรื่องที่ยังเปิด Q-15, Q-16 ใช้การอ่านตามตัวอักษรไปก่อน (`04` ส่วนที่ 6) — ถ้าร้านตอบต่างไป กระทบ BR-24 และ BR-11
- การออกแบบโดยทีม (`04` ส่วนที่ 6): รูปแบบรหัส การปัดเศษ ชั่วโมงฟรีต่อการจอง รูปแบบเบอร์โทร
