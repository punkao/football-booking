## 3. Impact (ก่อน diff)

### 3.1 แบบที่เลือก

ราคาที่มีวันมีผลอยู่ใน **DB** (คำตอบร้าน) เป็นตารางใหม่ `field_rates` — เก็บเฉพาะ "จุดเปลี่ยนราคา":

```
field_rates(field_id → fields, effective_from date, day_rate int, evening_rate int, PRIMARY KEY(field_id, effective_from))
```

- `fields.day_rate/evening_rate` = ราคา **ฐาน** (ก่อนจุดเปลี่ยนแรก) **ไม่แก้** → ถอย migration แล้วราคาเดิมกลับเอง · เว็บรุ่นเก่ายังคิดราคาเดิมได้ · ยอดที่เก็บในการจองไม่ถูกแตะ
- migration **008** `008_field_rates`: สร้างตาราง (IF NOT EXISTS) + ใส่ A, B `2026-11-01` = (ราคากลางวันเดิม, **1300**) `ON CONFLICT DO NOTHING` + `schema_migrations` 008 · down: DROP TABLE + ลบแถว 008 · เติม `\ir` ใน `db/init/01-schema.sql`
- seed `02-seed.sql`: ใส่แถว `field_rates` ชุดเดียวกัน (TRUNCATE `fields` CASCADE ล้างตารางลูกทุก reset) · ครอบด้วย `to_regclass` กัน reset ล้มเมื่อถอย 008 อยู่
- **กฎ (pure)** `rules/pricing.ts`: `Rates` เพิ่ม `rateChanges?: RateStep[]` · `ratesOn(field, date)` (จุดเปลี่ยนล่าสุดที่ `from ≤ date`) · `hourlyRate` เรียก `ratesOn` → **ผู้เรียกเดิมทุกจุด** (`fieldPriceFor`, ใบเสนอราคา, จอง, เลื่อนวัน, จองประจำ, ตารางว่าง, แชทรอบเต็ม) ได้ราคาตาม **วันเตะ** โดยไม่ต้องแก้ · `upcomingRates(field, today)`
- `loadFields/loadField` แนบ `rateChanges` (subquery เดียว) · `FieldRow.dayRate/eveningRate` = ฐาน
- **การแสดงผล "ราคาปัจจุบัน ณ วันนี้" (นาฬิกาแอป) + ราคาที่กำลังจะมีผล:**
  - `/api/fields`: `dayRate/eveningRate` = ราคา ณ วันนี้ (เดิม 800/1200 ที่ 9 ต.ค. → เทสต์ API เดิมผ่าน) + `rateChanges[]` เฉพาะที่ยังไม่ถึง
  - `/api/availability`: `fields[].dayRate/eveningRate` = ราคา ณ **วันที่ขอ** (ไม่เพิ่มคีย์ → golden `side` ไม่เปลี่ยน) · `slots[].price` ตามวันนั้นอยู่แล้ว
  - หน้า `/fields`: `field-day-rate-X` / `field-evening-rate-X` ข้อความ+`data-value` = ราคาปัจจุบัน **ตรงตัวเดิม** (`i18n.spec` `toHaveText('฿1,200')`) + แถวใหม่ `field-evening-rate-next-X` ("ตั้งแต่ 1 พ.ย. 2026 ฿1,300") ถ้ามีจุดเปลี่ยนข้างหน้า
  - หน้าแรก: ยัง **ไม่อ่าน DB** ตามเดิม (ออกแบบให้ขึ้นได้แม้ DB ล่ม) → `SEED_FIELDS` เพิ่ม `rateChanges` + อ่านนาฬิกาแอปแบบลองแล้วถอยไปเวลาเครื่อง · การ์ดแสดง "ก่อน 17:00 ฿800 · ตั้งแต่ 17:00 … ฿1,200 ต่อชั่วโมง" + `(฿1,300 ตั้งแต่ 1 พ.ย. 2026)` (`home-field-X-next-rate`) · เทสต์ **ตรวจว่า `SEED_FIELDS` = `/api/fields`** กันค่าซ้ำเพี้ยน
  - แชท: `FieldFact` เพิ่ม `rateChanges` (ที่ยังไม่ถึง) + `dayRate/eveningRate` = ราคา ณ วันนี้ → FACTS/prompt/mock/price guard ใช้ชุดเดียวกัน · ตอบราคาทั่วไปต่อท้ายราคาใหม่ · ถามเจาะวัน ("สนาม A เสาร์ 7 พ.ย.") ตอบตาม `ratesOn` ของวันนั้น · price guard อนุญาตราคาที่กำลังจะมีผล · ใบเสนอราคาในแชทมาจาก `evaluateBooking` ตัวเดียวกับเว็บ

ไม่เลือก: (ก) แก้ `fields.evening_rate` เป็น 1300 ตรง ๆ — ผิดทั้งวัน ก่อน 1 พ.ย. และไม่มีวันมีผล · (ข) ตารางราคาครบทุกช่วงเวลาแล้วทิ้งคอลัมน์เก่า — ต้อง migrate ข้อมูลเดิม เสี่ยงกว่า ถอยยากกว่า · (ค) หน้าตั้งราคา (G-33) — นอกขอบเขต
