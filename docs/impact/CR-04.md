## 3. Impact (ก่อน diff)

### 3.1 แบบที่เลือก

แก้ที่สมอง `lib/chat/mock.ts` ที่เดียว (ทั้ง MODE=mock และ mock-llm ใช้ไฟล์นี้) · ไม่แตะ `engine.ts` / price guard / `server/chat.ts` / การจอง (`collect`):

1. **`mergeContext(texts, facts)`** (ฟังก์ชันล้วน · export · มี unit) — เดินข้อความลูกค้าทั้งห้องตามลำดับ เก็บค่าล่าสุดของ `fieldId` `date` `startHour` `hours` `period` (ช่วงเย็น/กลางวัน) + `ask` (ว่าง/ราคา) + `cheapest` · ค่าใหม่ทับค่าเก่า · `cheapest` ดับเมื่อมีวันหรือเวลาเริ่มจริง
2. กฎเลือกคำตอบ (ลำดับ): ช่วงถูกสุด → ครบสนาม+วัน+เวลา → ราคาต่อชั่วโมงเมื่อขาดเวลา → ข้อความ "ถามกว้าง ๆ" เดิม · **ใช้ค่าจากห้อง เฉพาะเมื่อข้อความปัจจุบันเป็น "คำถามต่อ"** (มีคำว่าว่าง/ราคา/ถูกสุด หรือ ให้ค่าใหม่โดยไม่ใช่เรื่องอื่น: เวลาเปิด หลังคา ติดต่อ ทักทาย นอกเรื่อง) → "ขอบคุณครับ" / "เปิดกี่โมง" ไม่ถูกแย่ง
3. ชนิดคำตอบของคำถามต่อ: มีคำว่า "ว่าง" → CHECK · มี "ราคา" → QUOTE · ไม่มีคำทั้งสอง → ตามชนิดคำถามล่าสุดของห้อง (ถามว่างแล้ว "งั้นสนาม B ล่ะ" = CHECK) · ไม่เคยถาม = QUOTE (เดิม)
4. `extractField` เพิ่ม `pitch X` / `X pitch`
5. system prompt (`prompt.ts`) +1 บรรทัดสำหรับโมเดลจริง (ใช้ค่าที่คุยไว้ในห้อง ค่าใหม่ทับ)

ไม่เลือก: ให้ `server/chat.ts` สรุปบริบทแล้วฝังใน system prompt (กระทบ ai path ทั้งหมด + prompt snapshot) · ผ่อน price guard ให้ตัวเลขที่คำนวณเองผ่าน (ห้ามเปลี่ยน BR-30) · ขยายความจำไปการจอง (Q7)

## 5. Finding แยก (ไม่แก้ใน CR-04)

1. **ความจำยังไม่ครอบคลุมการ "จอง"** (Q7): ถาม "สนาม A พรุ่งนี้ 19:00 ว่างไหม" แล้วพิมพ์ "จองเลย" → น้องบอลถามสนาม/วัน/เวลาใหม่ทั้งหมด เพราะ `collect` เริ่มนับจากข้อความ "จอง" ล่าสุด (`mock.ts` ท่อนจอง) · หนังสือ CR-04 ไม่ได้ขอและการ์ดยืนยัน+PDPA ต้องไม่เปลี่ยน → ทำได้เป็น CR แยก ถ้าร้านต้องการ (ใช้ `mergeContext` ตัวเดิมเติมช่องที่ขาดก่อนถามได้)
2. **การ์ดราคาของ "ช่วงนั้น N ชั่วโมง" แสดงรอบตัวอย่าง** (วันทำการถัดไป 08:00): ข้อความตอบไม่พูดถึงวัน/รอบ แต่การ์ด (`chat-card-quote`) ที่แนบมาเป็นผลของ QUOTE จริงจึงโชว์รอบนั้น (ราคาถูกต้องตามฟังก์ชัน) · ถ้าร้านไม่อยากให้เห็นการ์ดนี้ ต้องมี flag ใน `engine.ts` ซ่อนการ์ด (แตะ engine/UI นอก CR นี้)
3. **ตอบราคาต่อชั่วโมงตามวัน (ไม่มี QUOTE)** อ่านวันหยุดจาก `FACTS.holidays` ซึ่ง prompt ใส่ไว้ 14 วันข้างหน้าเท่านั้น (`server/chat.ts` `systemPrompt`) → วันหยุดที่ไกลกว่า 14 วันจะถูกนับเป็นวันธรรมดา ในประโยค "ราคาต่อชั่วโมง" · ราคาจริงตอนลูกค้าให้เวลาเริ่มมาจาก QUOTE (ฟังก์ชันเว็บ) จึงถูกเสมอ
4. **TC-API-03 ล้ม 1 ครั้งบน firefox+webkit ในรอบ regression** (`SLOT_TAKEN` ที่ C 21 ต.ค. 23:00) — ไม่เกี่ยวแชท: KI `TC-STAFF-06` (CR-02) สุ่มจองช่องว่างของ C 21 ต.ค. อาจสุ่มโดน 23:00 ที่ TC-API-03 ใช้ (คอมเมนต์ใน `api.spec.ts:67` ว่า "ไม่มี test ไหนจอง" ไม่จริงอีกแล้วหลัง CR-02) · รันซ้ำเดี่ยวบน firefox/webkit ผ่าน · ข้อเสนอ: ให้ TC-STAFF-06 เลี่ยงชั่วโมง 23 หรือย้ายวัน (ไฟล์ `known-issues.spec.ts` แก้ได้ แต่ไม่แตะรอบนี้เพราะนอกขอบเขต CR-04)
