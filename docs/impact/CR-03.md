## 3. Impact (ก่อน diff)

### 3.1 แบบที่เลือก

ไม่แตะ `summarizeMoney` (แดชบอร์ดใช้ร่วม → ยอดเดิมคงเดิมแน่) เพิ่มฟังก์ชันล้วน 2 ตัวใน `rules/reports.ts` แล้วให้ `report()` เรียก:

1. **`splitBookingMoney(from, to, payments)`** → ต่อวัน `{ bookingPromptpay, bookingCash }` (PROMPTPAY / CASH_AT_FIELD ตามวันรับเงิน · CREDIT ข้าม) + ผลรวม
2. **`fieldUse(fieldIds, from, to, bookings)`** → ต่อสนาม `{ fieldId, hours, percent }` และต่อวัน `fieldHours` · นับ `CONFIRMED` `CHECKED_IN` `NO_SHOW` · `percent = round(hours ÷ (16 × วัน) × 1000) / 10`
3. `report()` เพิ่ม query อ่านอย่างเดียว `SELECT date, field_id, status, sum(hours)` + ฟิลด์ใหม่ `days[].bookingPromptpay/bookingCash/fieldHours` · `totals.bookingPromptpay/bookingCash` · `fieldUse[]` (ฟิลด์เดิมครบทุกตัว)
4. **CSV ต่อท้าย 8 คอลัมน์**: `มัดจำ/จ่ายผ่านพร้อมเพย์ (บาท)` · `เก็บหน้าสนาม (บาท)` · `ชั่วโมงใช้สนาม A` · `ใช้สนาม A (%)` · B · C (สลับชั่วโมง/% ต่อสนาม) · หัว 18 คอลัมน์เดิมไม่แตะ
5. **หน้าเว็บ**: ตารางเพิ่ม 2 คอลัมน์ต่อจาก "ยอดจอง" (`report-<วัน>-booking-promptpay` / `-booking-cash` · รวม `report-total-booking-promptpay` / `-cash`) + การ์ด "ชั่วโมงใช้สนาม" (`report-field-<A|B|C>-hours` / `-percent`)

ไม่เลือก: เปลี่ยน `summarizeMoney` ให้คืนช่องทาง (กระทบแดชบอร์ด JSON) · migration (ข้อมูลมีครบ ไม่ต้อง)
