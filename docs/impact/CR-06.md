## 3. Impact (ก่อน diff)

### 3.1 แบบที่เลือก

**เขียนแถว `payments` ตอนทีมรับจ่าย** (ในทรานแซกชันเดียวกับเครดิต) + **migration 009 เติมแถวย้อนหลัง** — ไม่แตะรายงาน/แดชบอร์ด/`summarizeMoney` (อ่านจาก `payments` อยู่แล้ว → ยอดทุกที่ถูกพร้อมกัน)

1. `challengePay` (`features.ts`): หลังเครดิต เพิ่ม `INSERT INTO payments(booking_id, amount, method, paid_at, challenge_id) VALUES (<การจองของเจ้าของ>, amount, 'PROMPTPAY', ctx.now, id)` เมื่อ amount > 0 · **เครดิต 3 บรรทัดเดิมไม่แตะ**
2. migration `009_challenge_payments.sql`:
   - `ALTER TABLE payments ADD COLUMN IF NOT EXISTS challenge_id int REFERENCES challenges(id)` (null = เงินจองปกติ) + `CREATE UNIQUE INDEX IF NOT EXISTS payments_challenge_once ON payments(challenge_id) WHERE challenge_id IS NOT NULL` → **คำท้า 1 ก้อน = เงิน 1 แถว** (กันซ้ำทั้งตอนรันซ้ำและตอนเว็บเขียน)
   - เติมย้อนหลัง: คำท้า `MATCHED` ทุกรายการ → แถว `PROMPTPAY` จำนวน/วันที่ = รายการเครดิต `CHALLENGE` ของการจองนั้น (`credit_entries` เป็นหลักฐานเวลา/จำนวนที่จ่ายจริง) · `ON CONFLICT DO NOTHING` · ห่อ `BEGIN…COMMIT` · ไม่แตะ `credit_entries` / `customers` / `bookings`
   - `009.down.sql`: ลบแถว `payments` ที่ `challenge_id IS NOT NULL` แล้ว drop index + คอลัมน์ + แถว `schema_migrations`
3. `db/init/01-schema.sql` เติม `\ir ../migrations/009_challenge_payments.sql` · `docs/RUNBOOK.md` ตาราง migration · `web/SPEC.md` (FR-44 + ตัวอย่าง version)

ไม่เลือก: (ก) เปลี่ยน `summarizeMoney`/`moneyRows` ให้ UNION `credit_entries` ของคำท้า — แก้ที่ผู้อ่านหลายจุด + ไม่มีแถวเงินให้ตามรอยตอนกระทบยอด · (ข) migration ไม่มีคอลัมน์ ใช้จับคู่ด้วย `(booking_id, amount, paid_at)` — รันซ้ำอาจซ้ำ/ลบผิดแถวได้

**ข้อสังเกตเรื่องถอยกลับ:** `009.down` ลบแถวเงินคำท้า **ทุกแถวที่ผูก `challenge_id`** (ทั้งที่เติมย้อนหลังและที่เว็บใหม่เขียนหลังขึ้น 009) เพราะหลัง drop คอลัมน์แยกไม่ได้ · ไม่เสียข้อมูล: ขึ้น 009 อีกครั้งจะเติมกลับจาก `credit_entries` ได้ครบ (ตรวจในข้อ 6) · แถวเงินจองปกติไม่ถูกแตะ · ตามกติกาเดิมของ migration 007/008 ต้องถอยเว็บกลับ image เดิมก่อน `--down`
