# IMPACT-TEMPLATE — แม่แบบของ `docs/impact/CR-0N.md` (บท 06 LAB 4 ข้อ 4)

ใช้ก่อนแตะโค้ดทุกครั้ง: **อธิบายของเดิม + วัด impact ก่อน diff** แล้วค่อยเขียนเทสต์แดง → แก้ (ลำดับเต็มอยู่ `legacy/CR-PROMPT.md`)
แม่แบบนี้เขียนย้อนจากฉบับที่ใช้จริง 6 ฉบับ (`docs/impact/CR-01.md` … `CR-06.md`) — **เก็บหัวข้อที่บท 06 กำหนดครบ และเพิ่มหัวข้อที่งานจริงต้องใช้ 4 อย่าง** (ทำเพิ่มเพราะ: ร้านต้องตอบก่อนเรารู้จักของเดิม · มีตัวเลขเงินจริงต้องเทียบก่อน/หลัง · ค่าคาดหวังเดิมอาจเปลี่ยนต้องรอ lead · ต้องมีวิธีถอยกลับก่อนแตะฐาน) ทำเครื่องหมาย ➕ ด้านล่าง

ป้ายแหล่งของค่าที่คาดหวัง (บังคับทุกค่า): `[D:CR-0N]` คำตอบร้านใน `CHANGE-REQUESTS/answers/README.md` · `[E golden/…:sha8]` หลักฐานจากระบบ (ใช้ล็อกของเดิมเท่านั้น) · `[R]` หลักสากล/คณิตศาสตร์ + เหตุผล · `[E]` ขัด `[D]` = ผู้ต้องสงสัยบั๊ก รายงาน ห้ามใช้เป็นค่าคาดหวัง

## โครงของไฟล์ (คัดลอกไปเริ่ม `docs/impact/CR-0N.md`)

```markdown
# Impact · CR-0N <ชื่อเรื่องสั้น>

หนังสือ: `CHANGE-REQUESTS/CR-0N.md` (<วันที่หนังสือ>) · ทีมดูแลระบบ · วิธีทำตาม `legacy/CR-PROMPT.md` · ต้นแบบ `docs/impact/CR-0M.md`
<สรุป 1–2 บรรทัด: ร้านขออะไร · อะไรต้องไม่เปลี่ยน>

## 1. คำถามถึงร้าน
เขียนจากหนังสือ + `legacy/SPEC-GAPS.md` + โค้ด (`legacy/SYSTEM-MAP.md` หัวข้อ I, L) **ก่อน** เปิด `CHANGE-REQUESTS/answers/README.md`
| # | อ้าง (G-xx / โค้ด) | คำถาม (ถามให้ตอบได้ด้วย ใช่/ไม่ หรือตัวเลข — ไม่เดาแทนร้าน) |
### 1.1 คำตอบร้าน   ← เติมหลังเปิดไฟล์คำตอบ · แต่ละข้อติดป้าย [D:CR-0N] และบอกว่ากระทบพฤติกรรมไหน
### 1.2 ถามร้าน (ยังไม่มีคำตอบ) · ใช้สมมติฐานที่ปลอดภัย   ← ➕ ทุกข้อที่ค้างต้องมีสมมติฐาน + ใครรับความเสี่ยง (ต่อเข้า RELEASE-NOTES / KNOWN-ISSUES)
### 1.3 ข้อตัดสิน (ร้านมอบให้ทีม)   ← ➕ เฉพาะเมื่อร้านตอบ "ให้ทีมตัดสิน": ผู้ใช้/lead ตัดสินว่าอะไร วันที่ เหตุผล

## 2. ของเดิมทำงานอย่างไร (CR-0N-BEFORE)
### 2.1 จากโค้ด   ← พฤติกรรมเดิมเป็นข้อ ๆ ทุกข้อมี `file:line` ที่เปิดดูแล้ว (ไม่เขียนจากชื่อไฟล์)
### 2.2 หลักฐานที่รันจริง   ← curl / psql อ่านอย่างเดียว / เทสต์ · วันที่ · `/api/version` · BUG_MODE · MODE · reset ก่อนหรือไม่ · ผลที่เห็นจริง (ตัวเลข) → เป็นค่า "ก่อน" ที่ใช้เทียบหลังแก้ ➕

## 3. Impact (ก่อน diff)
### 3.1 แบบที่เลือก   ← วิธีแก้ที่เล็กที่สุด · ที่วางกฎ (pure function ใน `web/lib/rules` ก่อน) · **ไม่เลือก** อะไรและเพราะอะไร
### 3.2 ไฟล์ × เทสต์
| ไฟล์ที่จะแตะ | เหตุผล (ข้อไหนของ CR) | ใครเรียกใช้ (grep ไฟล์:บรรทัด) | หน้าจอ / API / แชทที่กระทบ | ตาราง DB | เทสต์ที่ต้องรันซ้ำ | ความเสี่ยง |
### 3.3 DB · i18n · แชท · CSV · golden
| ด้าน | ผล |   ← DB: ต้องมี migration ไหม (เลขถัดไป + .down + รันซ้ำได้ + ข้อมูลเดิมต้องเท่าเดิม) · i18n TH/EN ครบ · แชทบอท (FACTS/prompt/mock/price guard) · CSV/รายงาน (ต่อคอลัมน์ท้ายเท่านั้น) · golden (`tests/golden` ต้องไม่เปลี่ยน ยกเว้น CR สั่ง) · BUG_MODE=1
### 3.4 ค่าที่คาดหวังเดิมที่ต้องเปลี่ยนตาม CR   ← ➕ แถวที่จะลง `ORACLE-CHANGES.md` (วันที่ | ไฟล์ | เคส | เดิม → ใหม่ | CR | ผู้อนุมัติ) · ทีม CR ไม่แก้เทสต์เดิมเอง รอ lead
### 3.5 grep "ค้นแล้วไม่เจอ"
- คำค้นที่ใช้ → ผล (ไม่มี / เจอที่ไหน)
- ที่อาจหลุด: ชื่อที่ประกอบจาก string · key i18n แบบ template · SQL ใน string · ผู้เรียกที่ต่อ URL (`` `/api/…${x}` ``)
- **grep ไม่เจอ ≠ ไม่มีผู้เรียก** → ยืนยันด้วยการรันเทสต์ หรือเขียนเป็นความเสี่ยง

## 4. เทสต์แดงก่อนแก้ (CR-0N-red)
เทสต์ใหม่ (ชื่อ · ไฟล์:บรรทัด · ค่าคาดหวัง + ป้ายแหล่ง) · ผลรันบนโค้ดเดิม: **ต้องแดงด้วยเหตุที่ถูก** (แนบข้อความที่ล้ม) · commit `CR-0N-red`

## 5. แก้ (CR-0N)
`git diff --stat` ต้องตรงตาราง 3.2 · commit `CR-0N`
### 5.x migration (ถ้ามี) — รันซ้ำ 2 ครั้ง + ถอยกลับ + ขึ้นใหม่ บนฐานที่มีข้อมูล ➕ ตัวเลขนับแถวทุกตารางก่อน/หลัง · ซ้อมถอยกลับของเว็บ (ลำดับ: เว็บก่อน แล้วฐาน)

## 6. ปลดล็อก known issue
ข้อใน `e2e/tests/cr/known-issues.spec.ts` ที่ CR นี้แก้ → ถอด `test.fail` (ไม่ถอด = "ผ่านโดยไม่คาด" = แดง) · อัปเดต `KNOWN-ISSUES.md`

## 7. ค่าคาดหวังเดิมที่เปลี่ยน (ORACLE-CHANGES)   ← ➕ แถวจริงที่ลงไฟล์แล้ว + ผู้อนุมัติ

## 8. Regression
`cd e2e && RUN_MIGRATION_TEST=1 node run-all.mjs` + `node tests/golden/check.mjs` · ตารางตัวเลข (ผ่าน/ล้ม/ข้ามต่อเบราว์เซอร์ · เทียบ `legacy/BASELINE.md`) · golden ที่ต่างอธิบายทีละกลุ่ม

## 9. ยังไม่ได้ทำ / ส่งต่อ
ข้อที่ร้านยังไม่ตอบ · ความเสี่ยงที่รับไว้ · ชื่อข้อใน `RELEASE-NOTES.md` / `KNOWN-ISSUES.md`
```

## เกณฑ์ตรวจก่อนบอกว่า impact "พร้อมแก้"

| ข้อ | ตรวจ | ผ่านเมื่อ |
|---|---|---|
| 1 | คำถามเขียนก่อนเปิดคำตอบร้าน | commit ของคำถามอยู่ก่อนคำตอบ หรือระบุในไฟล์ |
| 2 | พฤติกรรมเดิมมีหลักฐาน | ทุกข้อมี `file:line` + ผลรันจริงอย่างน้อย 1 ค่า |
| 3 | ตาราง 3.2 ครบ 7 คอลัมน์ | ทุกไฟล์มีผู้เรียก (grep) และเทสต์ที่ต้องรันซ้ำ |
| 4 | "ค้นแล้วไม่เจอ" บอกคำค้น | มีคำค้น + ที่อาจหลุดอย่างน้อย 1 ที่ |
| 5 | ค่าคาดหวังใหม่ทุกค่ามีป้ายแหล่ง | ไม่มีค่าที่ที่มาเป็น "ระบบตอบแบบนี้" |
| 6 | มีทางถอย | migration มี `.down` · เว็บถอยด้วย image เดิมได้ |
| 7 | เทสต์ใหม่แดงก่อนแก้ | commit `CR-0N-red` อยู่ก่อน `CR-0N` |
