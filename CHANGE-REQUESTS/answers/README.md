# คำตอบของร้านต่อคำถามเรื่อง CR (เปิดอ่าน **หลัง** เขียนคำถามของตัวเองใน `docs/impact/CR-0N.md` แล้วเท่านั้น)

ร้านตอบตามคำถามที่ทีมดูแลระบบมักถาม · ผู้ใช้ (ในฐานะเจ้าของสนาม) อนุมัติชุด CR นี้เมื่อ 20 ต.ค. 2569 · ถ้าคำถามของทีมไม่มีในนี้ ให้เขียนลง `docs/impact/CR-0N.md` หัวข้อ "ถามร้าน (ยังไม่มีคำตอบ)" แล้วรายงาน อย่าเดาเอง

## CR-01 ออกจากระบบ
- ยกเลิกเฉพาะ session ที่กดออกจากระบบ · เครื่องอื่นที่ยังเข้าสู่ระบบอยู่ใช้ต่อได้
- หลังออกจากระบบ cookie เดิมเรียกหน้าหรือ API ที่ต้องเข้าสู่ระบบ → ไม่ได้ (เหมือนไม่ได้เข้าสู่ระบบ: API ตอบ 401 · หน้าเว็บพาไปหน้าเข้าสู่ระบบ)
- ไม่ต้องทำ "ออกจากทุกเครื่อง" และไม่เปลี่ยนเวลาหมดอายุ session เดิม
- คนที่เข้าสู่ระบบอยู่ตอนอัปเดตระบบ ไม่ต้องเข้าสู่ระบบใหม่
- (ตอบเพิ่ม 20 ต.ค. 2569 · Q7 ใน `docs/impact/CR-01.md`) ช่วงผ่อนผัน cookie แบบเก่า: กดออกจากระบบเครื่องหนึ่งแล้วเครื่องอื่นที่ใช้ cookie แบบเก่าตัวเดียวกันหลุดด้วย → **ยอมรับได้** (ปลอดภัยกว่าให้ cookie ที่ออกจากระบบแล้วยังใช้ได้)

## CR-02 แก้ 5 จุด
1. เช็กอินได้ทุกเวลาของ **วันเตะ** (นับวันตามเวลาไทย) · วันอื่น → ปฏิเสธพร้อมข้อความบอกว่าเช็กอินได้เฉพาะวันเตะ · ชั่วโมงสะสมยังนับตอนเช็กอินเหมือนเดิม
2. "ใครกด" ใช้ชื่อที่แสดงของพนักงาน (เช่น น้องบอล) · ระบบอัตโนมัติ/ลูกค้าแสดงเหมือนเดิม · ประวัติเก่าที่บันทึกไว้แล้วแสดงชื่อพนักงานด้วย (ห้ามแก้แถวประวัติเดิม)
3. ขั้น "จบ" ขึ้นเมื่อการจองเช็กอินแล้ว **และ** เลยเวลาจบรอบ · เวลาของขั้น = เวลาจบรอบ · ไม่เพิ่มสถานะใหม่ในฐานข้อมูล · การจองที่ไม่มา/ยกเลิกไม่มีขั้น "จบ"
4. "3 เดือน" = วันสิ้นสุดไม่เกินวันเดียวกันของอีก 3 เดือน ถ้าเดือนนั้นไม่มีวันที่นั้นใช้วันสุดท้ายของเดือน · 30 พ.ย. → 28 ก.พ. ได้ · 30 พ.ย. → 1 มี.ค. ไม่ได้ · 1 ต.ค. → 31 ธ.ค. ได้ (เหมือนเดิม)
5. ค้นการจองโดยไม่กรอกรหัสหรือไม่กรอกเบอร์ → ข้อความบอกให้กรอกให้ครบ (ไม่ใช่ข้อผิดพลาดระบบ)

## CR-03 รายงาน
- "จ่ายผ่านพร้อมเพย์" = เงินค่าการจองที่รับทางพร้อมเพย์ในช่วง (นับตามวันรับเงิน) · "เก็บหน้าสนาม" = เงินค่าการจองที่รับเป็นเงินสดที่สนาม · สองช่องรวมกัน = "ยอดจอง" เดิม
- ตัวอย่าง 3–9 ต.ค. 2569: พร้อมเพย์ ฿6,600 · เก็บหน้าสนาม ฿600 (ตรง TEST-DATA)
- ชั่วโมงใช้สนาม = ชั่วโมงของการจองที่กันสนามและเวลาเตะอยู่ในช่วง (จ่ายแล้ว เช็กอินแล้ว ไม่มา) แยก A B C · เปอร์เซ็นต์ = ชั่วโมงที่ใช้ ÷ ชั่วโมงเปิด (16 ชม./วัน × จำนวนวัน) ปัดทศนิยม 1 ตำแหน่ง
- CSV: **เพิ่มคอลัมน์ใหม่ต่อท้าย** ห้ามย้ายหรือเปลี่ยนชื่อคอลัมน์เดิม (สูตร Excel ของร้านอ้างตำแหน่งคอลัมน์) · ยังเป็น UTF-8 มี BOM
- ยอดอื่น (ขายหน้าเคาน์เตอร์ หักเครดิต รวมรับเงิน) เหมือนเดิมทุกตัว

## CR-04 น้องบอลจำบทสนทนา
- จำเฉพาะในห้องแชทเดียวกัน · เปิดห้องใหม่ = เริ่มใหม่
- ข้อความใหม่ไม่บอกวัน/เวลา/สนาม/จำนวนชั่วโมง → ใช้ค่าล่าสุดที่คุยในห้อง · บอกค่าใหม่ → ใช้ค่าใหม่
- "it" / "สนามนั้น" = สนามล่าสุดที่คุย
- "ช่วงไหนถูกสุด" → ช่วงราคาถูกสุด (ก่อน 17:00 จ–ศ) พร้อมราคาต่อชั่วโมงของสนามที่คุยอยู่ หรือของสนาม 5 คนถ้ายังไม่ได้เลือก · ถามต่อ "2 ชั่วโมง" → คิดราคาจากช่วงนั้น
- ต้องทำงานทั้ง MODE=mock และ MODE=ai · การ์ดยืนยัน PDPA · ปฏิเสธนอกเรื่อง · ปิดเบอร์ · ห้ามเดาราคา — เหมือนเดิมทั้งหมด

## CR-06 เงินจากทีมรับคำท้า (ร้านตอบ 21 ต.ค. 2569)
- เงินที่ทีมรับคำท้าโอน **เข้าบัญชีพร้อมเพย์ของร้านจริง**
- ในรายงานนับในช่อง **"จ่ายผ่านพร้อมเพย์"** ตาม **วันที่รับเงิน** (รวมอยู่ใน "ยอดจอง" และ "รวมรับเงิน" ด้วย)
- คำท้าที่รับและจ่ายไปแล้วในอดีต **เติมบันทึกการรับเงินย้อนหลัง** ด้วย migration (รันซ้ำได้ ถอยกลับได้ · ไม่สร้างซ้ำ) ให้รายงานเดือนเก่าถูก
- เครดิตที่เจ้าของการจองได้ เหมือนเดิมทุกบาท

## CR-05 ราคาเย็นสนาม 5 คน
- ดู **วันเตะ**: เตะตั้งแต่ 1 พ.ย. 2569 ช่วงเย็น/วันหยุด สนาม A B = ฿1,300/ชม. · เตะก่อน 1 พ.ย. ราคาเดิม
- การจองที่สร้าง **ก่อน** ระบบใหม่ขึ้นใช้งาน ยอดเดิมทุกบาท (แม้เตะหลัง 1 พ.ย.) · ใบที่สร้างหลังขึ้นระบบใช้ราคาใหม่
- เลื่อนการจองเดิมไปรอบหลัง 1 พ.ย. หลังขึ้นระบบ → คิดราคาใหม่ตามกฎเลื่อนเดิม (แพงขึ้นจ่ายส่วนต่าง)
- จองคร่อม 17:00 คิดแยกรายชั่วโมงเหมือนเดิม · มัดจำ 50% ของ ฿1,300 = ฿650 · จองประจำลด 10% = ฿1,170 ต่อชั่วโมงเย็น
- เก็บราคาพร้อมวันมีผลในฐานข้อมูล (ไม่ฝังตัวเลขในโค้ด) · migration ต้องรันซ้ำได้และถอยกลับได้บนฐานที่มีข้อมูลจริง
