## CR-01 · ออกจากระบบแล้วยังเข้าใช้ต่อได้

ข้อเท็จจริง: cookie = ข้อมูลเซ็นด้วย HMAC ไม่มีสถานะฝั่ง server `[source server/crypto.ts:21-41]` · logout แค่สั่งเบราว์เซอร์ลบ `[source app/api/customers/logout/route.ts:5-9]` · cookie เดิมหลัง logout ยังได้ 200 `[E probe cr01]` · requirements ไม่มี FR/NFR เรื่อง logout หรืออายุ session `[REQ NFR-05 NFR-18]` · SPEC บอกแค่ `logout → { ok: true }` `[SPEC §5]`

| # | เรื่องที่ยังไม่ชัด | คำถามถึงร้าน |
|---|---|---|
| G-01 | CR เขียน "กดออกแล้วใช้ต่อไม่ได้จริง" และ "คนที่ไม่ได้กดใช้ต่อได้ตามปกติ" `[CR-01]` แต่บัญชีเดียวอาจเข้าจากหลายเครื่อง (คอมเคาน์เตอร์ + มือถือเจ้าของ) | กด "ออกจากระบบ" ที่เครื่องหนึ่ง ต้องตัด **เฉพาะเครื่องนั้น** หรือ **ทุกเครื่องของบัญชีนั้น** ครับ |
| G-02 | อายุ session ตอนนี้: ลูกค้า 30 วัน · ร้าน 12 ชั่วโมง `[source server/core.ts:157]` `[source server/auth.ts:51]` · ไม่มีหมดอายุเมื่อไม่ได้ใช้งาน | คอมเคาน์เตอร์ที่ใช้ร่วมกัน ต้องให้หลุดเองเมื่อไม่มีคนใช้กี่นาทีไหมครับ · 12 ชม. / 30 วัน ยังใช้ได้ไหม |
| G-03 | cookie `ln_access` (เบราว์เซอร์ที่สร้างการจองดูการจองนั้นได้ 30 วันโดยไม่ต้องกรอกเบอร์) `[source server/access.ts:7-12]` · ลูกค้าที่ไม่สมัครสมาชิกไม่มีปุ่มออกจากระบบ | สมาชิกกดออกจากระบบแล้ว ต้องลบสิทธิ์ "ดูการจองที่จองจากเครื่องนี้" ด้วยไหม · ลูกค้าทั่วไปที่ใช้เครื่องร่วม ต้องมีปุ่มลืมเครื่องนี้ไหมครับ |
| G-04 | ยังไม่มีฟีเจอร์เปลี่ยนรหัสผ่าน / ปิดบัญชีพนักงาน · `staff_users` ไม่มีสถานะ `[source mig/001_v1_baseline.sql:51-53]` | ถ้าพนักงานลาออกหรือรหัสหลุด ร้านต้องการ "ตัดทุกเครื่องของบัญชีนี้ทันที" ไหม (อยู่ใน CR-01 หรือแยกเป็น CR ใหม่) |
| G-05 | ตอนติดตั้งของใหม่ cookie เก่าทุกใบจะไม่มีบันทึกฝั่ง server | ยอมให้ **ทุกคนเข้าสู่ระบบใหม่ 1 ครั้ง** ตอนติดตั้งไหมครับ (CR เขียน "ไม่ต้องเข้าสู่ระบบใหม่ทุกคน" — หมายถึงหลังติดตั้งแล้วใช่ไหม) |
| G-06 | requirements ไม่มีข้อนี้ จึงยังไม่มีเกณฑ์ตรวจรับ | ขอเพิ่มเป็นข้อกำหนด (เช่น NFR "ออกจากระบบแล้ว cookie เดิมใช้ไม่ได้ภายใน X วินาที") ไว้ตรวจรับได้ไหมครับ |
